Bootstrap Pattern

Every API endpoint initializes via nsa_bootstrap():

<?php
declare(strict_types=1);
require_once dirname(__DIR__, 4) . '/Connector/_bootstrap.php';

nsa_bootstrap([
    'security' => true,        // Apply security headers
    'session' => true,         // Start session management
    'methods' => ['GET'],      // Allowed HTTP methods
    'json' => true,            // Set JSON content type
]);

API Creation Pattern

Standard REST Endpoint Template

<?php
declare(strict_types=1);

// 1. Include bootstrap
require_once dirname(__DIR__, 4) . '/Connector/_bootstrap.php';

// 2. Initialize with config
nsa_bootstrap([
    'security' => true,
    'session' => true,
    'methods' => ['GET', 'POST'],
    'json' => true,
]);

// 3. Authenticate
$userId = $_SESSION['user_id'] ?? null;
if (!$userId) {
    nsa_json_response(['success' => false, 'message' => 'Unauthorized'], 401);
}

// 4. Validate CSRF (for POST/PUT/DELETE)
if ($_SERVER['REQUEST_METHOD'] !== 'GET') {
    $csrf = $_POST['csrf_token'] ?? $_SERVER['HTTP_X_CSRF_TOKEN'] ?? '';
    if (!nsa_validate_csrf($csrf)) {
        nsa_json_response(['success' => false, 'message' => 'Invalid CSRF token'], 403);
    }
}

// 5. Get dependencies
$pdo = nsa_db();
$service = new ProfileService($pdo);

// 6. Process request
try {
    $data = $service->getProfile($userId);
    nsa_json_response([
        'success' => true,
        'data' => $data
    ]);
} catch (Exception $e) {
    nsa_log_error($e->getMessage());
    nsa_json_response([
        'success' => false,
        'message' => 'Internal server error'
    ], 500);
}

Response Format

Both projects use standardized JSON responses:

// Success
{
  "success": true,
  "data": { ... },
  "message": "Optional success message"
}

// Error
{
  "success": false,
  "message": "Error description",
  "errors": { ... }  // Optional validation errors
}

Security Implementation

1. Security Headers

// Applied via nsa_bootstrap(['security' => true])
Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline'
X-Frame-Options: SAMEORIGIN
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(), microphone=(), camera=()

2. CSRF Protection

// Generate token
$token = nsa_generate_csrf();
$_SESSION['csrf_token'] = $token;

// Validate token
$submitted = $_POST['csrf_token'] ?? $_SERVER['HTTP_X_CSRF_TOKEN'];
if (!nsa_validate_csrf($submitted)) {
    nsa_json_response(['success' => false, 'message' => 'CSRF validation failed'], 403);
}

3. Origin Validation

// In nsa_bootstrap()
$origin = $_SERVER['HTTP_ORIGIN'] ?? '';
$allowed = [
    'https://nexplacify.pro',
    'https://nileandsinai.com'
];

if (!in_array($origin, $allowed)) {
    header('HTTP/1.1 403 Forbidden');
    exit;
}

4. Rate Limiting

use Connector\Security\RateLimiter;

$limiter = new RateLimiter($pdo);
$identifier = $_SERVER['REMOTE_ADDR'] . ':' . $_SESSION['user_id'] ?? 'guest';

if (!$limiter->check($identifier, 60, 5)) {  // 5 requests per 60 seconds
    nsa_json_response(['success' => false, 'message' => 'Rate limit exceeded'], 429);
}

QueryBuilder Pattern

use Connector\Database\QueryBuilder;

$qb = new QueryBuilder($pdo);

// SELECT with conditions
$users = $qb->select('users')
    ->where('status', '=', 'active')
    ->where('created_at', '>', '2024-01-01')
    ->orderBy('id', 'DESC')
    ->limit(10)
    ->get();

// INSERT
$qb->insert('users', [
    'email' => 'user@example.com',
    'password' => password_hash($password, PASSWORD_ARGON2ID),
    'created_at' => date('Y-m-d H:i:s')
]);

// UPDATE
$qb->update('users', ['status' => 'verified'])
    ->where('id', '=', $userId)
    ->execute();

// DELETE
$qb->delete('users')
    ->where('status', '=', 'deleted')
    ->where('deleted_at', '<', date('Y-m-d', strtotime('-30 days')))
    ->execute();

Schema Best Practices

  • Use INT UNSIGNED for auto-increment IDs
  • Include created_at and updated_at timestamps
  • Add indexes on foreign keys and frequently queried columns
  • Use ENUM or VARCHAR with constraints for status fields
  • Normalize data but denormalize for read-heavy tables
  • Include soft delete columns (deleted_at) for audit trails

Implementation Checklists

API Endpoint Creation

  1. Create file in appropriate Api/ subdirectory with semantic naming
  2. Add declare(strict_types=1) at the top
  3. Include Connector/_bootstrap.php with correct relative path
  4. Call nsa_bootstrap() with security, session, methods, and json flags
  5. Implement authentication check and return 401 if unauthorized
  6. Validate CSRF token for mutating operations (POST/PUT/DELETE)
  7. Instantiate required service classes with PDO dependency
  8. Wrap business logic in try-catch with proper error responses
  9. Return standardized JSON response with success boolean
  10. Log errors with nsa_log_error() for monitoring
  11. Test endpoint in both authenticated and unauthenticated states

Service Class Creation

  1. Create file in Assets/Services/ under appropriate domain folder
  2. Use namespace matching directory structure
  3. Add strict type declaration
  4. Inject PDO (and other dependencies) via constructor
  5. Keep methods focused on single responsibility
  6. Use QueryBuilder for complex queries, prepared statements otherwise
  7. Return typed arrays or objects (use return type hints)
  8. Throw domain-specific exceptions for error conditions
  9. Document public methods with PHPDoc blocks
  10. Write unit tests for business logic

Database Schema Creation

  1. Name file with semantic versioning (tablename_v1.sql)
  2. Store in Assets/Extras/Sqls/
  3. Include IF NOT EXISTS in CREATE statements
  4. Define primary keys as INT UNSIGNED AUTO_INCREMENT
  5. Add foreign key constraints with ON DELETE/UPDATE actions
  6. Create indexes on foreign keys and query-heavy columns
  7. Include created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  8. Include updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
  9. Add comments explaining non-obvious column purposes
  10. Document schema changes in Assets/Extras/Updates/

Security Checklist

  1. Enable security headers via nsa_bootstrap(['security' => true])
  2. Validate all user inputs with Sanitizer and Validator helpers
  3. Use parameterized queries (never string concatenation for SQL)
  4. Implement CSRF protection on all state-changing operations
  5. Check origin header against whitelist for AJAX requests
  6. Apply rate limiting to authentication and sensitive endpoints
  7. Hash passwords with PASSWORD_ARGON2ID (never MD5 or SHA)
  8. Use HTTPS in production (check with nsa_enforce_https())
  9. Implement proper session management with fingerprinting
  10. Log security events for audit trail
  11. Never expose internal error details to clients
  12. Set restrictive file permissions on .env and sensitive configs

Pre-Deployment Checklist

  1. All .env.example variables documented with example values
  2. composer.lock committed to version control
  3. Database migrations tested on clean database
  4. All API endpoints return proper HTTP status codes
  5. Error logging configured and tested
  6. Security headers verified with browser dev tools
  7. CSRF protection tested with invalid tokens
  8. Rate limiting tested under load
  9. Authentication flows tested (login, logout, session expiry)
  10. Authorization checks verified for protected endpoints
  11. SQL injection attempts blocked by parameterized queries
  12. XSS protection verified through output escaping
